Sightmap is an open YAML format and CLI that maintain a shared memory of a web app for AI agents. A `.sightmap/` directory checked into your repo names the app's views, components, and API requests; `memory` notes record the quirks, invariants, and shortcuts source code never states. Agents curate the map against the running app, definitions link back to their source files, and every agent that follows reads the same map.

## What an agent sees

The same page, two snapshots — an agent opening a `<DepartureDatePicker>` on a flight-search form:

<CodeGroup>

```text Bare accessibility tree
uid=1_0  RootWebArea "Book a flight"
uid=1_3  textbox "Departure date"
uid=1_8  button "Previous Month"
uid=1_9  button "Next Month"
uid=1_10 generic "July 2025"
uid=1_19 gridcell "Choose Tuesday, July 1st, 2025"
uid=1_20 gridcell "Choose Wednesday, July 2nd, 2025"
uid=1_21 gridcell "Choose Thursday, July 3rd, 2025"
         ...28 more gridcells...
```

```text With a sightmap
[View: FlightSearch "/search"]
[Guide]
- DepartureDatePicker accepts typed YYYY-MM-DD
  // skips opening the calendar
- Arrow keys navigate the grid; Enter selects; Esc closes
- Past dates render but are aria-disabled
- Range: 1st click = start, 2nd = end, 3rd resets

uid=1_0  RootWebArea "Book a flight"
uid=1_1  FlightSearchForm visible
uid=1_3    DepartureDatePicker [src: src/components/DatePicker.tsx] visible interactive
uid=1_4      date-input visible interactive
uid=1_8      prev-month visible interactive
uid=1_9      next-month visible interactive
uid=1_10     month-label "July 2025" visible
uid=1_19     day "Choose Tuesday, July 1st, 2025" visible interactive
         ...30 more days...
```

</CodeGroup>

Without a sightmap: no view name, no component identity, no hint the textbox accepts typed dates. The agent's only path forward is brute force. With one: it knows which view it's on, that the picker has a typed-input shortcut, that past dates look interactive but aren't, and that the source file is one click away.

**One artifact, learned once, shared across every agent.**

## How Sightmap works

<Steps>
  <Step title="Install the CLI and skills">
    `npm install -g @sightmap/sightmap` gives you the `sightmap` binary; `sightmap skills install` adds the `sightmap-authoring` and `sightmap-browser` skills to your agent harness.
  </Step>
  <Step title="Start a browser session">
    `sightmap browser start` launches Chrome plus a local server that hot-reloads the corpus whenever YAML changes.
  </Step>
  <Step title="Let an agent iterate">
    The agent runs `sightmap iterate <url>` per route: snap the page, see which interactive nodes are still unattributed, add components, re-snap — until every view reports zero orphaned nodes.
  </Step>
  <Step title="Check it in">
    `sightmap validate`, `lint`, and `report` keep the corpus honest. Commit `.sightmap/`, and every agent that touches the app — coding agents, browser agents, runtime tools — reads the same map.
  </Step>
</Steps>

<Note>
Sightmap is an open, MIT-licensed specification with a single shipped implementation: the `sightmap` CLI and Go library. The spec, CLI, conformance fixtures, and these docs all live in one repo at [github.com/sightmap/sightmap](https://github.com/sightmap/sightmap).
</Note>
