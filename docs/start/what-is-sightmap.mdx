Sightmap is an open specification for a `.sightmap/` directory checked into your repo. Its YAML files name your app's `views` (URL routes), `components` (CSS selectors), and `requests` (API routes). They also store `memory` notes about runtime quirks, invariants, and shortcuts that source code does not explain. A `sitemap.xml` lists pages for search engines. A `.sightmap/` gives Sightmap-enabled tools semantic context about how the app works.

## Why agents need it

A browser exposes roles, accessible names, and DOM attributes. It does not identify the current product view, connect a rendered component to its source file, or explain runtime behavior such as keyboard shortcuts and disabled states. Without that context, each agent has to reconstruct the same relationships from the DOM and source.

Sightmap-enabled clients add view names, component names, source paths, and relevant `memory` notes to browser snapshots. Because the YAML is checked in, those observations remain available after the agent's session ends.

## Who reads it

Sightmap-enabled tools that drive or analyze the running app read the directory. Coding agents use it to find the source file for the current view or component before editing. Browser agents use semantic component names instead of guessed selectors. Sightmap originated in [Subtext](https://subtext.fullstory.com), a runtime product that adds sightmap names and memory to live session snapshots and replays. Other clients can read the YAML directly or use Sightmap's Go library.

## What it gives you

A sightmap gives views, components, and requests semantic names that can link back to source files. `memory` entries record facts such as "Past dates render but are aria-disabled" and "POST /api/search debounces 300ms." Sightmap-enabled clients put relevant notes in a `[Guide]` section at the top of each enriched snapshot so an agent does not have to rediscover them.

The format is plain YAML validated against a [public JSON Schema](/reference/json-schema). You can review and version it with the rest of your code, and consuming it does not require a hosted service.
