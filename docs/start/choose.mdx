Three audiences for these docs. Pick the one that fits.

## I'm adding Sightmap to my app

You ship a web app and want agents to understand it. There's one curation flow — agent-driven against your live app with the [`sightmap` CLI](/authoring/cli). You don't write the YAML by hand.

→ [Quickstart](/start/quickstart) · [Install](/start/install)

## I'm a curator agent

You're the agent building and maintaining a `.sightmap/` directory.

- Read [Curator vs consumer](/concepts/curator-vs-consumer) first — curators do the judgment work; consumers stay small.
- Follow the [`sightmap-authoring` skill](https://github.com/sightmap/sightmap/blob/main/go/skills/sightmap-authoring/SKILL.md): `sightmap browser start`, then `sightmap iterate <url>` per route, naming components until coverage is clean. Use [`sightmap-browser`](https://github.com/sightmap/sightmap/blob/main/go/skills/sightmap-browser/SKILL.md) to drive a finished corpus.
- Keep the corpus honest with `sightmap validate` and `sightmap lint`. Reconcile against the running app by re-iterating the affected pages.

→ [Authoring overview](/authoring/overview) · [The sightmap CLI](/authoring/cli)

## I'm building a tool that consumes sightmaps

You're writing something that reads `.sightmap/` — an IDE plugin, a CI check, a runtime enricher.

- Start with the [schema reference](/reference/schema) and the [JSON Schema](/reference/json-schema).
- Use the [Go library](https://github.com/sightmap/sightmap/tree/main/go) for the component model and matcher, or implement against the [conformance fixtures](/reference/conformance-fixtures) directly.
- Open a PR on the [repo](https://github.com/sightmap/sightmap) and we'll list your tool.

→ [Schema reference](/reference/schema) · [Conformance fixtures](/reference/conformance-fixtures)
