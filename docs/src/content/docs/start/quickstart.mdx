---
title: "Quickstart"
description: "From install to a populated .sightmap/ — agent-driven, against your running app, with the sightmap CLI."
---

One curation flow: an agent drives your live app with the `sightmap` CLI and writes `.sightmap/` from what it observes. Works for any web app the CLI can reach — local dev, a preview deploy, or a hosted URL. You don't write the YAML by hand.

## 1. Install the CLI and skills

```bash
npm install -g @sightmap/sightmap        # or: npx @sightmap/sightmap ...
# or from source:
go install github.com/sightmap/sightmap/go/cmd/sightmap@latest

sightmap skills install                  # sightmap-authoring + sightmap-browser skills
```

`sightmap skills install` drops the two agent skills into `~/.agents/skills` (override with `--target`). Any skills-aware agent (Claude Code and others) picks them up and follows the authoring playbook.

## 2. Start a browser session

```bash
cd my-app                 # your project (a .sightmap/ will be created here)
sightmap browser start    # launches Chrome + a corpus server that hot-reloads YAML
sightmap browser status   # ● running
```

## 3. Let an agent bootstrap the corpus

Point your agent at the app and let the `sightmap-authoring` skill drive:

> Bootstrap a sightmap for this app. Start a browser session, iterate over the main routes, and name the interactive components until coverage is clean.

Under the hood the agent runs the edit-verify loop:

```bash
sightmap iterate 'http://localhost:3000/'          # snap + coverage for a route
sightmap sel-probe '[data-testid="product-pod"]'   # verify a candidate selector
# ...add components to .sightmap/*.yaml, then re-iterate
```

`iterate` scores every interactive node **T1** (named), **T2** (inside a named component), or **T3** (orphaned), and suggests selectors for the orphans. The agent adds components until a view reports `0 orphaned`.

## 4. Check the corpus

```bash
sightmap validate     # structural correctness (non-zero exit on error)
sightmap lint         # advisory quality checks
sightmap report       # per-view T1/T2/T3 health table
```

Result:

```
.sightmap/
  app.yaml             # global components, top-level notes
  products.yaml        # one file per top-level route
  account.yaml
  shared.yaml          # cross-route components
```

## Iterate

- **For selector stability**, add `data-component="ComponentName"` to the source where no stable selector exists — the matcher scores it highest.
- **When source changes** — new route, renamed component — re-run `sightmap iterate` on the affected pages. Existing `memory`, `properties`, and selector choices are preserved; new orphans surface in coverage.
