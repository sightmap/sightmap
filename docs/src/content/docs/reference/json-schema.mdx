The Sightmap v1 JSON Schema is the machine-readable contract for `.sightmap/*.yaml` files. [JSON Schema](https://json-schema.org/) is a standard for describing the shape of structured data; despite the name it validates YAML just as well as JSON, since YAML is a superset of JSON's data model. This page covers that machine-readable file (editor and CI setup); for the human-readable field-by-field walk-through, see the [Schema reference](/reference/schema/).

The schema is published in the repo and addressable by a stable `$id` URL.

| | |
|---|---|
| Spec stream | `1` |
| Draft | JSON Schema 2020-12 |
| `$id` | `https://raw.githubusercontent.com/sightmap/sightmap/main/spec/v1/sightmap.schema.json` |
| Source | [`spec/v1/sightmap.schema.json`](https://github.com/sightmap/sightmap/blob/main/spec/v1/sightmap.schema.json) |

For a human-readable walk-through of the same fields, see the [Schema reference](/reference/schema/).

## yaml-language-server directive

Paste this comment as the first line of any `.sightmap/*.yaml` file to opt into editor validation, autocomplete, and hover docs:

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/sightmap/sightmap/main/spec/v1/sightmap.schema.json
version: 1
views:
  - name: Home
    route: /
```

The directive is recognized by the [Red Hat YAML language server](https://github.com/redhat-developer/yaml-language-server), which most editor integrations use under the hood.

## VS Code

1. Install the [YAML extension by Red Hat](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml).
2. Either add the `# yaml-language-server: $schema=…` directive at the top of each file, or wire the schema globally in your workspace settings:

```json
{
  "yaml.schemas": {
    "https://raw.githubusercontent.com/sightmap/sightmap/main/spec/v1/sightmap.schema.json": [
      ".sightmap/**/*.yaml",
      ".sightmap/**/*.yml"
    ]
  }
}
```

## JetBrains (IntelliJ, WebStorm, PyCharm)

JetBrains IDEs ship with a JSON Schema mappings UI:

1. **Settings → Languages & Frameworks → Schemas and DTDs → JSON Schema Mappings**
2. Add a mapping with the `$id` URL above as the schema URL and `.sightmap/*.yaml` as the file pattern.

The inline `# yaml-language-server: $schema=…` directive is also honored.

## Neovim

Most LSP setups for Neovim wrap the same Red Hat language server. Configure `yamlls` with the schema mapping, or rely on the inline directive.

## CI validation

Validate `.sightmap/*.yaml` against the schema with any JSON-Schema 2020-12 validator pointed at the `$id` above. The repo ships a small [ajv](https://ajv.js.org/)-based checker used to validate the spec's own examples and conformance fixtures:

```bash
# from a checkout of sightmap/sightmap
cd spec && npm install && node scripts/validate-sightmap.mjs <dir>
```

Point it at any directory of `.sightmap/` YAML.
