# AGENTS.md — docs/

Guidance for agents editing the Sightmap documentation site (Mintlify).

## Ground truth

- The spec (`../spec/v1/`) is normative for the YAML format. On any
  disagreement between a docs page and `spec/v1/schema.md` or
  `sightmap.schema.json`, the spec wins.
- The Go CLI (`../go/`) is the only shipped implementation. Document only
  commands and flags that exist in `sightmap <command> --help` output — never
  invent flags, and never document the retired JS/Python SDK surface
  (`init`, `fmt`, `check`, `match`, `explain` are not commands).
- `reference/schema.md` is generated by `scripts/sync-spec.mjs` — edit the
  spec and regenerate; never edit the page.

## Page conventions

- Frontmatter is exactly three double-quoted keys, in order: `title`
  (Title Case, SEO-long), `sidebarTitle` (1–3 words), `description` (one
  benefit sentence). No `icon`, `mode`, or `keywords`.
- In-page headings are sentence case. Commands stay backticked even in
  headings.
- Internal links are root-relative without extensions: `/start/quickstart`.
- Every code block has a language tag; fence titles are filenames or short
  captions.
- Components: `<Steps>` for procedures, `<Note>`/`<Tip>`/`<Warning>` callouts,
  `<CardGroup cols={2}>` for navigation hubs, `<CodeGroup>` for variants.
  Parameters are plain markdown tables. No images.
- CLI reference pages: one `### \`command\`` section per command separated by
  `---`, each with a short description, a flags table, an example invocation,
  and realistic output in a ```text block that matches what the binary
  actually prints.
- New pages must be added to `docs.json` navigation.

## Style

Active voice, second person. No marketing language in docs. Example commands
must be copy-pasteable and match the real CLI surface.
